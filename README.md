## ١) ما كان مكسورًا وتم إصلاحه في هذا التحديث

> 🧭 **للشرح المبسّط خطوة بخطوة (لغير المبرمجين): افتح ملف `ابدأ-من-هنا.md`** — مكتوب فيه كل ضغطة زر بالتفصيل.

| المشكلة | الأثر الذي كنت تراه | الإصلاح |
| --- | --- | --- |
| `src/db/index.ts` كان يوقف البرنامج إذا لم يجد `DATABASE_URL` وقت **البناء** | فشل النشر على Vercel برسالة `DATABASE_URL is required` | أصبح الاتصال **كسولًا (Lazy)**: لا يُنشأ إلا عند أول استعلام فعلي، فينجح البناء دائمًا |
| لا يوجد أي إعداد SSL لمكتبة `pg` | أخطاء `self-signed certificate in certificate chain` مع Neon | نتحكم بـ SSL يدويًا ونتجاهل `sslmode` القادم من الرابط (سبب الخطأ في نسخ `pg` الحديثة) |
| الكود يقرأ `DATABASE_URL` فقط | إذا كانت تكاملة Neon تضيف `POSTGRES_URL` يظهر خطأ «رابط غير مضبوط» | دعم `DATABASE_URL` و `POSTGRES_URL` و `DATABASE_URL_UNPOOLED` و `POSTGRES_URL_NON_POOLING` وغيرها |
| `drizzle.config.json` كان يحتوي رابط **محليًا** مثبّتًا في الكود | استحالة تحديث جداول Neon من جهازك | استُبدل بـ `drizzle.config.ts` يقرأ الرابط من البيئة |
| لا توجد جداول ولا سكربتات تهيئة | خطأ 500 بعد تسجيل الدخول: `relation "users" does not exist` | ملف `src/db/schemaSql.ts` + نقطة `/api/setup` + أوامر `npm run db:push` و `npm run db:seed` |
| لا يوجد ملف `.gitignore` | رفع مجلد `node_modules` والملفات السرّية إلى GitHub (فشل الرفع وتسريب الأسرار) | أُضيف `.gitignore` كامل |
| لا يوجد ملف يشرح متغيّرات البيئة | لا تعرف أي متغيّر تضع في Vercel | أُضيف `.env.example` (قالب جاهز) |
| مجلد `public/images` غير موجود | صور مكسورة في شاشة الدخول وبطاقات المنتجات | أُضيفت صور مؤقتة بنفس الأسماء في `public/images` |
| رسائل الأخطاء عامة (مثل «تعذر تسجيل الدخول») | صعوبة معرفة سبب العطل | كل أخطاء قاعدة البيانات تُترجم الآن إلى رسالة عربية واضحة (كلمة مرور خاطئة/جداول غير موجودة/انتهت المهلة...) |
| نقطة `/api/health` كانت تُرجع `{ok:false}` فقط | لا تعرف أين المشكلة | أصبحت تقول لك: هل الرابط مضبوط؟ من أي متغيّر؟ هل الاتصال يعمل؟ هل الجداول جاهزة؟ |
| جلسة الدخول بدون `secure` في الإنتاج | ثغرة أمنية بسيطة | أُضيف `secure` في بيئة الإنتاج |

> ⚠️ **مهم جدًا:** تم فحص جهازك ووجدنا أن **Node.js** و **Git** غير مثبّتين عليه بشكل طبيعي (يوجد فقط نسخة Node مدمجة مع برنامج Adobe Creative Cloud ولا تصلح للاستخدام من طرفية النظام). لذلك لا يمكنك تشغيل `npm install` أو رفع الملفات إلى GitHub من خلال الطرفية في الوقت الحالي. الأوامر البديلة لكل خطوة مذكورة في هذا الدليل (الطريقة السهلة لا تحتاج تثبيت أي شيء).

## ٢) الطريقة السهلة: من الصفر إلى موقع يعمل (بدون أوامر على جهازك)

### الخطوة ١ — إنشاء قاعدة بيانات على Neon
1. ادخل إلى [neon.com](https://neon.com) وأنشئ حسابًا (يمكنك التسجيل بحساب GitHub).
2. أنشئ مشروعًا (Create project) واختر أقرب منطقة (Region) — مثل `eu-central-1` إن كنت في مصر/الشام.
3. من صفحة المشروع اضغط **Connection Details** واختر **Connection string**.
4. انسخ الرابط. شكله يكون مثل:
   `postgresql://USER:PASSWORD@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`
   - **مهم:** استخدم الرابط الذي يحتوي `-pooler` (المجمّع) للتطبيق.
5. احفظ الرابط في مكان آمن — ستحتاجه في Vercel.

> الأسهل: من Vercel استخدم **Marketplace ← Neon** لربط قاعدة البيانات تلقائيًا، وسيضيف Vercel المتغيّرات بنفسه فلا تحتاج للنسخ اليدوي.

### الخطوة ٢ — رفع الملفات إلى GitHub
**أ. بدون تثبيت أي برنامج (رفع يدوي):**
1. ادخل [github.com](https://github.com) ← **New repository** ← اختر اسمًا (مثال: `sohob-liquids`) واجعله **Private** ← Create.
2. اضغط **uploading an existing file**.
3. اسحب **محتوى** مجلد المشروع نفسه (مجلد `src`, والملفات: `package.json`, `package-lock.json`, `next.config.ts`, `tsconfig.json`, `drizzle.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `.gitignore`, `README.md`, `.env.example`, ومجلد `public`) — **ولا ترفع مجلد `node_modules` ولا `.next` أبدًا**.
4. اكتب رسالة ثم **Commit changes**.

**ب. إن ثبّتت Git و Node.js لاحقًا (الأفضل):**
```bash
git init
git add .
git commit -m "تهيئة المشروع"
git branch -M main
git remote add origin https://github.com/اسم-حسابك/sohob-liquids.git
git push -u origin main
```
ملف `.gitignore` سيحمي الأسرار ويمنع رفع `node_modules` تلقائيًا.

### الخطوة ٣ — النشر على Vercel وربط قاعدة البيانات
1. ادخل [vercel.com](https://vercel.com) وسجّل بحساب GitHub.
2. **Add New ← Project** ← اختر المستودع الذي رفعته ← **Import**.
3. Vercel سيكتشف Next.js تلقائيًا: **لا تغيّر** Build Command ولا Output Directory (اتركها افتراضية).
4. قبل الضغط على Deploy، افتح **Environment Variables** وأضف:

   | Name | Value | البيئات |
   | --- | --- | --- |
   | `DATABASE_URL` | رابط Neon المجمّع (الذي فيه `-pooler`) | Production + Preview + Development |
   | `SETUP_TOKEN` | رمز من اختيارك (٨ أحرف على الأقل، مثال `Sohob-Setup-2026`) | Production (لتشغيل التهيئة) |

   - إن ربطت Neon من **Vercel Marketplace ← Neon** فسيُضاف `DATABASE_URL` تلقائيًا، وتخطّ هذه الخطوة.
   - بعد إضافة أي متغيّر يجب عمل **Redeploy** حتى يُقرأ.
5. اضغط **Deploy** وانتظر انتهاء البناء.

### الخطوة ٤ — تهيئة الجداول (إنشاء بنية قاعدة البيانات)
اختر **واحدة** من الطريقتين:

**الطريقة أ — من المتصفح (بدون أي برنامج على جهازك):**
افتح هذا الرابط في المتصفح (بدّل النطاق، وتأكد أن `SETUP_TOKEN` مضبوط في Vercel):
```
https://نطاق-موقعك.vercel.app/api/setup?token=Sohob-Setup-2026
```
إذا ظهرت رسالة نجاح فالجداول أُنشئت وحساب المدير جاهز.
> بعد نجاح التهيئة: **احذف** متغيّر `SETUP_TOKEN` من Vercel وأعد النشر لتعطيل هذه النقطة نهائيًا.

**الطريقة ب — من جهازك (تحتاج Node.js):**
```bash
npm install
npm run db:push     # إنشاء/تحديث الجداول في Neon
npm run db:seed     # (اختياري) بيانات تجريبية: منتجات وعملاء وفواتير
```
لتعمل هذه الأوامر على Neon: انسخ `.env.example` إلى `.env.local` والصق رابط Neon في `DATABASE_URL`.

### الخطوة ٥ — تسجيل الدخول
- افتح موقعك، وسجّل الدخول بـ `admin` / `admin123` (**غيّر كلمة المرور فورًا من صفحة الإعدادات**).
- للتحقق من صحة الربط في أي وقت: افتح `https://نطاق-موقعك.vercel.app/api/health` وستظهر حالة قاعدة البيانات بالعربي.

### الخطوة ٦ — (اختياري) تطوير محلي على جهازك
1. ثبّت **Node.js LTS** من [nodejs.org](https://nodejs.org) (النسخة 20 أو 22).
2. ثبّت **Git** من [git-scm.com](https://git-scm.com) إن أردت استخدام الأوامر.
3. في مجلد المشروع:
```bash
npm install
npm run dev
```
ثم افتح `http://localhost:3000`.

## ٤) حل المشاكل الشائعة

| ما تراه | السبب | الحل |
| --- | --- | --- |
| فشل البناء على Vercel برسالة فيها `DATABASE_URL` | متغيّر البيئة غير مضبوط في المشروع | أضفه في Settings ← Environment Variables (اختر البيئات الثلاث) ثم Redeploy |
| `جداول قاعدة البيانات غير موجودة بعد` | قاعدة Neon جديدة وبلا جداول | افتح `/api/setup?token=...` أو نفّذ `npm run db:push` |
| `self-signed certificate in certificate chain` | مشكلة SSL مع Neon | تم إصلاحها في الكود تلقائيًا (اتصال مشفّر). أعد النشر بأحدث نسخة من الكود |
| `كلمة مرور قاعدة البيانات غير صحيحة` | رابط Neon ناقص أو كلمة المرور تغيّرت | انسخ الرابط من Neon ← Connection Details وحدّث `DATABASE_URL` |
| `انتهت مدة الاتصال` أو `تم قطع الاتصال` | استخدام رابط غير مجمّع مع Serverless | استخدم الرابط الذي يحتوي `-pooler` في المضيف |
| `عدد الاتصالات كبير` | كثرة النسخ المتزامنة | استخدم الرابط المجمّع، أو قلّل `PG_POOL_MAX` |
| شاشة الدخول ترجع لصفحة الدخول بلا سبب | الجلسة منتهية أو قاعدة البيانات غير متصلة | افتح `/api/health` لمعرفة الحالة، ثم أعد تسجيل الدخول |
| الصور تظهر مكسورة | `public/images` غير موجود | الصور المؤقتة أُضيفت. استبدلها بصورك بنفس الأسماء (`login-art.jpg`, `p-mango.jpg`, ...) |
| فشل البناء بسبب ESLint | قواعد صرامة في بيئة Vercel | في `next.config.ts` أضف: `eslint: { ignoreDuringBuilds: true }` مؤقتًا ثم أصلح التحذيرات لاحقًا |
| نسيت كلمة مرور المدير | — | أضف `SETUP_TOKEN` في Vercel ثم افتح `/api/setup?token=الرمز&resetPassword=كلمة-مرور-جديدة` — بعدها احذف المتغيّر |

### نقاط مهمة عند رفع تحديثات جديدة
- بعد أي تعديل في الجداول (`src/db/schema.ts`) شغّل `npm run db:push` قبل النشر.
- عند دمج Neon عبر Vercel Marketplace: كل Preview Deployment يحصل على فرع قاعدة بيانات منفصل مع متغيّراته تلقائيًا.

## ٥) ملاحظات أمنية
- لا ترفع `.env.local` أو أي ملف يحتوي رابط قاعدة البيانات إلى GitHub (محمي في `.gitignore`).
- احذف `SETUP_TOKEN` من Vercel بعد انتهاء التهيئة.
- غيّر كلمة مرور `admin` الافتراضية فور أول دخول، ولا تشارك روابط `/api/setup`.
- الاتصال بـ Neon مشفّر دائمًا. إن أردت تحققًا كاملًا من الشهادة أضف `DB_SSL_STRICT=true` أو شهادة CA في `DATABASE_CA_CERT`.

## ٧) متطلبات البيئة
- **Node.js 20.9 أو أحدث** (موصى به 22 LTS) — مضبوط في `package.json` ضمن `engines`. Vercel سيستخدم Node 22 تلقائيًا.
- **PostgreSQL 14+** (Neon يوفر ذلك افتراضيًا).
- ملف `package-lock.json` مرفق مع المشروع ليجعل تثبيت الحزم على Vercel سريعًا وثابتًا — لا تحذفه.

> ملاحظة: الصور في `public/images` هي صور مؤقتة أُنشئت لتشغيل التصميم. استبدلها بصورك الحقيقية بنفس الأسماء (مقاس `login-art.jpg` 1600×1000 وبطاقات المنتجات 800×800) دون تعديل أي كود.

| إعدادات SSL | فحص منطق الاتصال | ✅ نحذف `sslmode` من الرابط (سبب خطأ الشهادة) ونمرّر `ssl` بأنفسنا |
